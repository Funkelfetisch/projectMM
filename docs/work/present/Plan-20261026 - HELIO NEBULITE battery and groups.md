## Measurement and transport contract

Keep battery capability, physical presence and measurement validity separate.
An AC-only/minimal board has no pack instances. A battery-capable board with
unverified presence or unsupported/failed ADC reads reports unknown, not zero.
Each pack carries its own source revision, calibrated ADC millivolts, nominal
divider conversion, timestamp, stale state and optional percentage estimate.
A missing qualified voltage-to-charge model keeps percentage unknown; the old
WLED offset/curve is not activated as calibration. Charging state needs its
own qualified status input; it is not derived from USB or voltage movement.

The S3 two-pack snapshot needs ADC2 support with the SDK's oneshot arbitration,
not continuous ADC2 or forced hardware workarounds. ADC timeout results are
invalid and must never replace the last valid sample with zero. Verify the
exact SDK and actual Wi-Fi/BLE coexistence before accepting that board.
The product HAL now accepts these S3 pins through calibrated oneshot reads; choosing a historical profile still does not establish the board revision or physical measurement accuracy.

Divider-gate writes now serialize with sampler shutdown. A worker detached after the platform's bounded stop cannot subsequently switch a pin already given to a new owner; ADC reads do not hold the gate lock. Host tests exercise the late-worker ordering, but real pin timing and ADC/Wi-Fi coexistence still require the physical board.

The sampler rejects two active independent packs on the same ADC, any active ADC/sense-gate pin collision, and opposite polarities on a shared sense gate. An invalid live configuration does not schedule another old-config sample. Two separately sensed packs may use the same gate with the same polarity. A shared Y-connected battery rail remains one measured channel rather than two invented readings.

Invalid configuration is explicitly reported to the web dashboard and RPC battery response. The dashboard masks previously cached measurements and presents a configuration error, including when no valid slot can be identified. This is not a battery-presence or charge reading.

For standard BAS, a known absent battery differs from an unknown measurement:
BAS 1.1 recommends level zero for a battery known to be absent. The implemented custom telemetry carries presence; the optional standard Battery Level Status characteristic is omitted. The product UI must still show absent rather
than "0% empty". Unknown/stale measurements must not be published as invented
current percentages. AC-only profiles expose no fictitious BAS battery.
Multi-pack identities/CPF descriptors need checked SIG assigned numbers and
service discovery tests. Bluetooth qualification and Android status-bar behavior remain open. Both native product variants compile. The identified HELIO test device passes the optional BAS metadata and bonded-reconnect checks below; battery hardware accuracy remains unqualified.
