# BLE re-pair recovery

Native133 on Mi9 encounters 11 protected State reads rejected with ATT0f and 11 peripheral SMP PairingFailed08 responses after the legitimate Android Forget action. Its capture contains no encryption change and no RPC command writes. The App owner explicitly returns the HELIO device window for firmware diagnosis/repair and retains Mi9/foreground ownership for a separate Basic4/Zengge test. Firmware uses Linux independently.

The installed a41701b9 runtime is independently identified by MAC, build and size, with no retained panic. Its source logs the repeat-pairing event and returns zero. The pinned IDF6.1 NimBLE implementation permits continuation only after RETRY1 and successful removal of that peer's bond; IGNORE2 and zero terminate the repeat check. Packet reason08 fits this defect but alone does not prove that the runtime callback occurred. The retained Linux bond independently passes an encrypted State read before repair, with zero command writes.

The working-tree correction adds one explicit three-minute, single-use repair window. It starts closed. Replacing a bond requires the actual connection identity, an unencrypted connection, new bonding, Secure Connections, a 16-byte key and no authentication downgrade. The window is consumed before deletion; the helper bounds the synchronous repeat loop. Only that identity is deleted. SDK deletion is not transactional: failures block protected GATT access and request disconnection. A compile-time guard rejects the SDK automatic-deletion option, which would bypass this policy. Native counters expose repeat requests and acknowledged deletions separately from pairing success.

This is repair of the existing encrypted Just Works transport, not an owner-account protocol or production security approval. A peer identity address is a storage lookup key rather than proof of owner or old-key possession. Cryptographic ownership, physical claim, offline delegated grants, transfer/recovery and RTC-independent expiry need a separate reviewed proposal before implementation. The existing RPC2 envelope and authorization limits remain unchanged.

The owner explicitly requires optional control authorization and a separate optional crowd-location feature. Ordinary lighting needs no mandatory account claim. Guest, offline and transfer/recovery paths remain requirements. Community Find My/Find Hub feasibility research covers OpenHaystack, GoogleFindMyTools and biemster/FindMy; it authorizes no tracker flash, provider account, agreement or cost. Key rotation, private-key custody and control/advertising coexistence require source and device qualification before a product promise. This research follows the immediate re-pair repair and App pilot return.

Required acceptance: focused SDK-fixture security/failure tests; shared host tests; native HELIO compile; one identified OTA preserving current settings and unrelated bonds; encrypted reconnect with the existing Linux bond; scoped preset/UI/API checks where safe; explicit App handback with installed identity and catalogue. The actual Mi9 forgotten-bond repair then needs App-side native consent, EncryptionChange, protected read and fresh correlated RPC2 commands. Never turn source, fixture or Linux reconnect evidence into Mi9 first-pair acceptance. No all-bond wipe, customer flash or new firmware/App owner is authorized.

## Actual Native133 acceptance

The App owner's positive HCI report confirms completed secure-connections DHKey checks, enabled encryption, a protected read before hello and 51 fresh correlated RPC2 responses. Twenty-four unique scene pages finish with a null cursor; battery correctly reports no packs and BAS0. The observed native counters are repeat1/deleted1/full2/unknown0, confirming that both full-table prechecks reach the intended scoped replacement.

The App owner verifies individual power and a Basic3/Basic5/HELIO group with actual readbacks. After a Mi9 Bluetooth off/on cycle, the group reconnects automatically from zero to three members. Independent target HCI confirms stored-bond encryption without a new SMP request, fresh hello and all 24 scene pages. It records one preceding transient connection failure, not uninterrupted connection success. The rotated captures remain separate.

Cleanup removes the temporary group and closes App links while retaining the new Mi9 bond. Drivers match the baseline; Ripple and curves remain unchanged. The historical panic record remains present and unchanged. The App expressly retains the exclusive lease for an independent Native134 warm reconnect; the firmware owner does not reclaim it by elapsed time. Optical output, actual batteries, multiple-HELIO timing and cross-vendor animation equivalence remain outside these results.
