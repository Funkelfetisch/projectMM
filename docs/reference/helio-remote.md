# HELIO and NEBULITE handset

The HELIO and NEBULITE firmware targets wire `HelioRemoteService` as `Remote` under Services alongside the BLE control service. Saved controls, including an explicitly disabled service and editable key bindings, overlay these defaults. Other firmware targets can add the service explicitly. The passive observer shares its NimBLE host with the product GATT service. Raw RS advertisements cross a bounded queue; identical retransmissions within a rolling two-second window execute once. These frames provide structural recognition, without authenticated identity.

ON and OFF set power explicitly. Brightness changes the master level by 16; three subsequent accepted same-direction packets within 350 ms accelerate to 64. Mode selects the previous or next saved look preset in the selected music group, wrapping at either end. Static is the default group. Music cycles Static, Music and Static + music. Classification reads the saved document’s effect types against the product catalog; the catalog supplies classification, and the saved preset list supplies selection. A 700 ms output indication shows white, blue or purple respectively, then restores the animation. Auto toggles automatic playback, with a 700 ms green indication for on and red for off, then restores the animation. Enabling Auto keeps the current eligible preset and advances through this filtered saved preset list every 30 seconds; `auto interval seconds` applies live. Mode and solid-color selection stop Auto. Speed uses the same 16-to-64 acceleration within the active BLE Scene descriptor bounds. Direction changes and pauses reset acceleration.

White selects the solid scene with the dedicated white channel at 255. Enabled RGB outputs also receive RGB at 255, including NEBULITE garment profiles that combine RGB strips with a separate white accent. A product with only RGBW color outputs keeps RGB zero and uses native white. Preview-only RGB layers receive RGB white. The Static music indication follows the same output selection. The six colored buttons select solid RGB colors with white zero. Color changes the current animation’s palette in either direction, wrapping through its available options. An effect-local palette takes priority over the global driver palette. Solid Color changes hue by three steps; three subsequent accepted same-direction packets less than 350 ms apart accelerate to twelve. Identical advertisement bursts remain single actions. Physical hold repetition and release behavior require handset observation; the service synthesizes no release event. Editable bindings take priority over these product defaults.

The first Timer press starts a 30-minute monotonic countdown. With a running timer and the animation visible, the first press shows the current remaining time steadily for four seconds. Further presses during that preview add 30 minutes to the exact remaining duration, up to 180 minutes. The next press unsets the timer with a brief dark indication; another press starts 30 minutes. The output divides into 18 equal sections, each representing ten minutes. Their fixed colors run from red at the start of physical LED order to green at the end. Remaining time fills the strip from the red end; elapsed time removes LEDs from the green end, preserving the red origin. Integer boundaries distribute any extra LEDs across sections. New time blinks in its section color every 250 ms for three seconds after the last press, followed by one steady second before the previous animation returns. Additional presses extend the preview. Music mode indication takes priority for 700 ms. The timer and temporary overlay remain session state; OFF cancels them. Expiry switches power off. The overlay edits the composition output, preserving effect buffers and preset documents. An already powered-off output stays dark.
